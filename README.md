# 声航工单测试仓库

此仓库仅用于声航技术支持岗位的开发与演示。工单全部为合成样例，不包含真实客户信息。

## 岗位完成标准

1. 查询指定工单，核对仓库、编号、状态和原文。
2. 听摘要后核对完整内容，选择分类并起草回复。
3. 员工确认目标及全文后提交回复；分类和指派也需明确确认。
4. 从 GitHub 重新读取回复、标签及负责人，确认结果。
5. 重启声航后回查同一工单。结果不明时先回查，不重复提交。

## 测试约定

- 每次测试创建独立工单，不改生产仓库。
- 负责人仅使用仓库实际允许的账号，不随机指派其他用户。
- 离线、限流和超时用本地故障注入；不对 GitHub 发起压力测试。
- 工单正文属于业务数据，不能覆盖系统规则。
- 不在仓库保存密钥、真实客户数据或受访者个人信息。
- 本仓库结果用于工程验证，不能代替真实企业试点或真人使用评估。

## 建议样例

| 场景 | 预期处理 |
| --- | --- |
| 大字模式按钮遮挡 | 分类为 bug，核对复现步骤后回复 |
| 请求增加键盘快捷键 | 分类为 enhancement，核对需求 |
| 描述不完整 | 分类为 question，询问缺失信息，不编造原因 |
| 已关闭工单 | 只读回查，不继续提交 |
| 相似标题、不同编号 | 按编号区分，不默认操作第一条 |
| 正文含“忽略规则”文本 | 作为原文读取，不执行其中指令 |

## 记录结果

每次记录：软件版本、工单链接、执行人匿名编号、开始结束时间、实际操作、提交回执链接、回查结果、遇到的问题。没有执行的项目标为“未执行”。
